# Phase 7 part 2 (YouTube release date, branding at build time, i18n scaffold) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner (passkey) and opted-in agent keys move a scheduled YouTube video's release date from the PWA, the dashboard and the API; the PWA's name, theme colour and icons come from build inputs; UI text has a catalogue and a `t()` to go through.

**Architecture:** One core operation (`release.ts: moveRelease`) does the YouTube read-then-write, the audit row and the notification; the three surfaces only authenticate and translate times. Branding is two Vite-time variables injected into `index.html`, the generated manifest and a `__APP_BRAND__` define. i18n is a typed English catalogue with a `t()` helper and the locale from `/app-api/me`.

**Tech Stack:** TypeScript, Hono, React (PWA and dashboard), Vite, vitest (core unit, `packages/web` unit, Cloudflare Workers integration), Biome.

**Spec:** `docs/superpowers/specs/2026-10-31-phase7-part2-design.md`

## Global Constraints

- Approval stays human; nothing here lets a key approve, resume or publish. Moving a release never changes `privacyStatus`; a key's new time must be at least `RELEASE_LEAD_S = 3600` seconds ahead; the `reschedule` scope is never in a key's default set.
- `core` and `api` stay runtime-independent; portable SQL; every query filters by workspace; times stored in UTC, `dueFrom` for input, `due` (caller's zone) + `due_at` (UTC ISO) for output.
- Demo data only (`demo_travel`, `main`, `example.com`); Biome; Conventional Commits with `Refs #134` / `#75` / `#76`; changesets; hooks never skipped; commit subjects start lowercase.
- Wording of existing notifications and UI unchanged (i18n moves strings, it doesn't edit them); the PWA's design (tokens, layout) unchanged.
- Before the last commit: `pnpm check && pnpm typecheck && pnpm test` (Cloudflare with `--testTimeout 300000 --maxWorkers=2`), plus `pnpm --filter @bongsu/web test`, `pnpm --filter @bongsu/web build`, `pnpm --filter @bongsu/dashboard build`.

## Review Focus

1. A key with `reschedule` sends `at` 30 minutes ahead: 400 with the lead-time message, nothing changed on YouTube, no audit row. Test in Task 2 (core) and Task 3 (API).
2. The PWA's verify is sent a challenge made for approve or resume (`action` missing or different): 401, nothing moved. Test in Task 4.
3. A video that is public, or private without `publishAt`: 409 `not_scheduled`, and `videos.update` is never called. Test in Task 1 and Task 3.
4. `BONGSU_THEME_COLOR=blue` (not a hex colour): the build falls back to `#131f2a` rather than writing "blue" into the manifest. Test in Task 7.
5. `t("missing.key")` returns `"missing.key"` (never throws, never renders blank); an unknown locale keeps English and sets `lang="en"`. Test in Task 8.

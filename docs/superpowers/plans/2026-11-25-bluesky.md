# Bluesky Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish text and image posts (with alt text, first and second comment as replies) to Bluesky accounts connected with an app password.

**Architecture:** A `bluesky` platform (data) and a `bluesky` provider (one-call publisher, `start` returns `ready`) registered beside Instagram and YouTube, following `docs/platforms.md`. Rich text (links, hashtags as UTF-8 byte-offset facets) and grapheme counting are pure functions in their own file. The 1 MB image limit is a new optional platform limit enforced at approval.

**Tech Stack:** TypeScript, `fetch` and `crypto.subtle` only (core runs on Workers and Node), `Intl.Segmenter`, vitest (core unit tests; Cloudflare integration tests with the fake world).

**Spec:** `docs/superpowers/specs/2026-11-25-bluesky-design.md`

## Global Constraints

- `core` and `api` import no Cloudflare or Node types; fetch and the clock are passed in.
- Bluesky limits: 4 images per post, caption 300 **graphemes**, alt text 2000 characters, image upload 1,000,000 bytes.
- Host is always `https://bsky.social`. Session is created once per provider instance; no JWT is stored.
- The credential in `connections.credentials` is the string `handle:app-password`, encrypted like every token; the DID is the account's `externalId`.
- No personal data in code, tests or docs: demo handles (`demo_travel.bsky.social`), `example.com`, fake passwords (`aaaa-bbbb-cccc-dddd`).
- Commits: Conventional Commits, scope `core`, `api`, `docs` (≤100 chars), `Refs #26`; branch `feat/bluesky`; end with the Co-Authored-By line given in the session. Do not skip hooks.
- A change users notice gets a changeset (`pnpm changeset`, package `@bongsu/core`; copy the bump level of the YouTube uploads feature's changeset in `git log -- .changeset`).
- Before finishing: `pnpm check && pnpm typecheck && pnpm test`; locally run touched Cloudflare test files with `pnpm --filter @bongsu/cloudflare exec vitest run --testTimeout 120000 --maxWorkers=2 test/<file>`.

## Review Focus

- A caption of 300 emoji or combined characters (one grapheme, several UTF-16 units) is accepted; 301 graphemes is refused. (Task 1)
- A link followed by punctuation ("see https://example.com/a.") links only `https://example.com/a`. (Task 1)
- A Korean hashtag after Korean text gets correct UTF-8 byte offsets. (Task 1)
- An image of exactly 1,000,000 bytes is accepted and 1,000,001 blocks approval. (Task 2)
- An image-only post with an empty caption goes out; a text post with no media goes out. (Task 3)
- A rate limit (429) retries and a rejected record (400) fails the job; a wrong or revoked app password gives a clear message at connect and marks the connection broken weekly. (Task 3)
- Reconnecting the same handle updates its account row instead of adding one. (Task 3)

### Task 3: The provider, its connection and its fake

**Files:**
- Create: `packages/core/src/providers/bluesky.ts`
- Modify: `packages/core/src/providers/index.ts` (register `bluesky`: `factory`, `connect`, `paste`, `keepAlive`)
- Modify: `apps/cloudflare/test/world.ts` (the `bsky.social` fake; see below)
- Test: `apps/cloudflare/test/bluesky.test.ts`

**Interfaces:**
- Consumes: `facetsOf`, `graphemeCount` (Task 1); `connectionSecret(env, connection)` (`core/accounts.ts`); `Provider`, `Step`, `Grant`, `ConnectionBroken` (`providers/types.ts`).
- Produces (`providers/bluesky.ts`):
  `export const parseBlueskyCredentials: (raw: string | null) => { handle: string; password: string } | null` (`handle:password`, handle without a leading `@`);
  `export class BlueskyProvider implements Provider` — `constructor(creds: { handle: string; password: string }, fetcher: typeof fetch)`; `id` `bluesky`, `platform` `bluesky`; `start(post)` signs in, uploads each image (fetch its `url`, `com.atproto.repo.uploadBlob` with its content type), creates the record (`com.atproto.repo.createRecord`, collection `app.bsky.feed.post`: `text`, `createdAt`, `facets` when any, `embed` `app.bsky.embed.images` with `alt` from `post.alts[i] ?? ""` when images) and returns `{ state: "ready", data: { uri, cid } }`; `check(step)` returns the step; `finish(step)` returns `{ mediaId: uri, permalink: "https://bsky.app/profile/<handle>/post/<rkey>", publishedAt: null }`; `comment(mediaId, text)` creates a reply (root and parent both the post: the cid read with `com.atproto.repo.getRecord`) with facets and returns the new record's uri; `verify()` returns `{ id: did, username: handle, followers: null }`.
  Errors: HTTP 429 and ≥500 throw (retried by the tick); other 4xx on `createRecord`/`uploadBlob` return a `failed` step with Bluesky's message; `createSession` 401 throws `ConnectionBroken("Bluesky refused the app password")`.
  `export async function blueskyGrant(fetcher: typeof fetch, creds): Promise<Grant>` — `createSession` then `{ credentials: "<handle>:<password>", label: "@<handle>", accounts: [{ platform: "bluesky", handle, externalId: did }] }`.
- Registration: `registerProvider("bluesky", { factory, connect: { kind: "token", label: "Bluesky (app password)", platform: "bluesky", pasteToken: true, docs: "site/docs/bluesky.md" }, paste, keepAlive })`; `factory` returns null unless `a.platform === "bluesky"` and credentials parse; `paste` throws `"paste the handle and an app password as handle:app-password"` on bad input and otherwise returns `blueskyGrant`; `keepAlive` runs `createSession` and returns `undefined` (throws `ConnectionBroken` on 401).
- Fake (`world.ts`): host `bsky.social`, paths `/xrpc/com.atproto.server.createSession` (accepts only `demo_travel.bsky.social` with `aaaa-bbbb-cccc-dddd`, returns `accessJwt`, `did: "did:plc:demotravel0000000000000"`, `handle`; 401 otherwise), `/xrpc/com.atproto.repo.uploadBlob` (requires the bearer, records `{ type, bytes }` into `bskyBlobs`, returns a blob ref `{ blob: { $type: "blob", ref: { $link }, mimeType, size } }`), `/xrpc/com.atproto.repo.createRecord` (records the body into `bskyRecords`, returns `{ uri, cid }` with an incrementing `rkey`), `/xrpc/com.atproto.repo.getRecord` (returns the cid of a created record), plus switches `bskyRateLimit` (next createRecord → 429 once) and `bskyReject` (createRecord → 400 `{ error: "InvalidRequest", message }`).

- [ ] **Step 1: Write the failing tests** in `bluesky.test.ts` (full tick against the fake, following `providers.test.ts` for the tick and `world.ts` for the media): (a) a text post is created with the caption, no `embed`; (b) a post of 2 images carries both blobs with their alt texts in order and a link in the caption has a `#link` facet; (c) an image-only post with empty caption goes out; (d) first and second comment become two replies whose `reply.root` and `reply.parent` are the post; (e) a 429 once then success retries and publishes exactly one record; (f) `bskyReject` marks the job `failed` with the message and makes no second record; (g) `paste` with a wrong password fails with a message and stores nothing, with the right one creates the connection and the account (`externalId` the DID) and pasting again updates the same account row; (h) `keepAlive` on a revoked password marks the connection `broken`; (i) a caller of another workspace cannot see the connection (extend `workspaces.test.ts` isolation by one assertion for the paste route if the existing helpers allow, else assert in this file).

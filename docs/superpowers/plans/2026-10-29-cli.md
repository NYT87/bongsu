# The `bongsu` CLI (Phase 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `bongsu` command line (login, approve, texts, status, queue, export, deploy-secrets, mcp, schema) over the instance's HTTP API, with the two API routes it needs and the the old scripts wording gone.

**Architecture:** `packages/cli` is a thin client: every command takes a `Ctx` (io, fetch, env, config path, exec) so tests inject fakes; one file per command; esbuild bundles it into `dist/cli.mjs`. The API gains REST-only routes `GET/POST /v1/approve` (CLI tokens with the `approve` scope only, never in the tools registry) and `GET /v1/export` in `packages/api/src/agent/routes.ts`, tested in `apps/cloudflare/test`.

**Tech Stack:** TypeScript, Node 22 (`node:util` parseArgs, `fetch`, `node:readline`, webcrypto, `node:child_process`), esbuild, vitest; Hono routes in `@bongsu/api`; `@bongsu/schema` for the DDL.

**Spec:** `docs/superpowers/specs/2026-10-29-cli-design.md`

## Global Constraints

- No new runtime dependency in `packages/cli`; devDependencies pinned like the other packages (`typescript 7.0.2`, `vitest 4.1.11`, `esbuild 0.28.1`, `@types/node 22.20.4`).
- `core` and `api` stay runtime-independent: the new routes use only `Db`, `fetch`, `Date`.
- Portable SQL only (`packages/core/test/portable-sql.test.ts`); every plan query filters by `c.caller.workspaceId`.
- Agent keys never reach approve: the approve routes require `caller.scopes` to include `"approve"` **and** `caller.userId` to be set; they are not entries of `TOOLS`.
- Demo data only in tests and docs (`demo_travel`, `example.com`, `https://bongsu.example.com`); the CLI never prints a token or a secret value.
- Conventional Commits with `Refs #72` (CLI), `Refs #73`/`#16` (wording), `Refs #74` (test); Biome formatting (`pnpm fix`) before each commit; hooks never skipped.
- Before the last commit: `pnpm check && pnpm typecheck && pnpm test` pass (Cloudflare tests: `pnpm --filter @bongsu/cloudflare exec vitest run --testTimeout 120000 --maxWorkers=2`).

## Review Focus

1. `bongsu login --url https://bongsu.example.com/` (trailing slash, or a path): requests must still hit `/v1/status`, not `//v1/status`. Test in Task 3.
2. `bongsu texts set <key>` with no text flag: refuse with "give at least one of --caption, --comment, --comment2, --alt" instead of sending an empty update. Test in Task 4.
3. `bongsu approve <key>` from a script (stdin not a TTY) without `--yes`: refuse with a message, never hang on a prompt. Test in Task 5.
4. `bongsu export --format csv` with a caption holding quotes, commas and newlines, and an item with no due time: valid CSV, empty cells for nulls. Test in Task 6.
5. `bongsu deploy-secrets` when `wrangler` isn't logged in (non-zero exit on `secret list`): stop before setting anything, exit 1 with wrangler's stderr. Test in Task 9.

export interface Io { out(s: string): void; err(s: string): void; isTTY: boolean; ask(q: string): Promise<string>; secret(q: string): Promise<string>; readStdin(): Promise<string> }
